# smart-bid-platform-fe 架构说明

> 本文以 `src/`、`vite.config.ts` 和当前 Java Controller 契约为准，最后按当前代码复核于 2026-08-09。路由、HTTP 路径或响应字段变动时，应先更新实现和类型，再同步本文与 `frontend-architecture.drawio`。

## 1. 运行边界

前端是 Vite + Vue 3 + TypeScript 的单页应用，使用 Hash History，因此浏览器地址形如 `/#/bid-inviter`。开发服务器只把业务前缀代理到 Java 服务 `http://localhost:8080`；浏览器不会直接调用 Python 服务。

```text
浏览器
  → Vue 页面 / shared 组件
  → src/api/*.ts
  → src/api/http.ts（HTTP Basic + Result 错误归一化）
  → Vite proxy
  → Java 平台
       ├─ to-markdown：文件 → Markdown
       └─ chat-agent：向量化、检索与问答
```

前端不生成文件 object key、SHA-256、转换状态、向量化状态或权限结论。这些均由 Java 和下游服务维护，前端只保留页面交互所需的临时状态。

## 2. 目录与依赖方向

```text
src/
├── api/                 HTTP、SSE 和业务端点封装
├── composables/         两种角色登录态、分页等可复用状态逻辑
├── router/              Hash 路由与本地登录态导航守卫
├── shared/
│   ├── components/      可复用页面部件和文件面板
│   ├── errors/          ApiError
│   └── utils/           显示字典、下载、格式化和错误文案
├── types/               与 Java 请求/响应字段对齐的 TypeScript 类型
└── views/
    ├── bid-inviter/     招标方登录、首页和业务页面
    ├── supplier/        投标方登录、投标和我的投标
    └── common/          角色选择和 404
```

依赖方向保持 `views → api/types/shared → http`。`shared` 不导入具体页面；角色差异通过页面传入的 API、状态列和行标识适配，不复制通用文件列表模板。

## 3. 路由与角色入口

当前共有 16 条路由：15 个明确入口和 1 个 404。所有页面按需懒加载。

| 路径 | 组件/用途 |
| --- | --- |
| `/` | `RoleSelector.vue`，选择角色 |
| `/bid-inviter`、`/bid-inviter/login` | 招标方首页、登录 |
| `/bid-inviter/invitation/{list,create,edit/:id}` | 招标公告管理 |
| `/bid-inviter/bid-handler-info/{list,create}` | 招标经办人管理 |
| `/bid-inviter/bid-record/list` | 招标方查看投标记录、风险分析入口 |
| `/bid-inviter/risk-analysis/list` | 风险分析历史 |
| `/supplier`、`/supplier/login` | 投标方首页、登录 |
| `/supplier/invitation/list` | 可投标项目列表 |
| `/supplier/bid-record/create?invitationId=N` | 创建投标记录并上传资信材料 |
| `/supplier/my-bids` | 当前投标方的投标记录与资信材料详情 |
| `/:pathMatch(.*)*` | 404 |

路由守卫只读取本地凭据，负责把未登录用户引到对应登录页；它不是安全边界。后端仍对每个受保护请求校验 HTTP Basic 凭据和资源归属。

## 4. 登录、HTTP 和 SSE

`useBidderAuth` 与 `useBidInviterAuth` 分别维护投标方和招标方的账号信息。`http.ts` 根据 URL 前缀选择本地凭据：`/bidder/**` 使用 `bidderCredentials`，其他业务前缀使用 `bidInviterCredentials`，并注入 `Authorization: Basic …`。无效 JSON 只清理当前角色的凭据，不能影响另一角色会话。

响应先由 `http.ts` 统一识别 `Result<T>` 的业务失败，再归一为 `ApiError`；页面使用 `getErrorMessage` 展示稳定错误码或网络错误。

原生 `EventSource` 不能附带 Basic Header，因此 `api/sse.ts` 用 `fetch` 读取 `text/event-stream`，断线后 3 秒重连。文件状态的事实源始终是数据库：收到 `file-status` 事件后，页面重新请求列表，而不是用事件载荷直接覆盖行状态。

## 5. 文件上传、状态刷新和下载

### 5.1 通用文件上传组件

`shared/components/FileUploadPanel.vue` 是不感知业务类型的文件上传与生命周期面板。调用方注入标题、列表、上传、删除、重试、下载、详情、状态列和事件订阅适配器；组件本身不导入知识文件或资信文件 API。

交互约定：

- 可一次选择多个文件，统一点击“上传文件”批量提交；
- 待上传文件行只有 X 图标用于移除；
- 上传期间禁用再次提交和移除；批量请求失败时恢复本次待上传选择；
- 文件名右侧使用统一下载图标，弹窗按可用状态提供“下载原文件”或“下载 .md”；
- 有 `subscribeUpdates` 时只由 SSE 驱动列表刷新；没有 SSE 适配器时才使用有限次数的兜底轮询。

### 5.2 知识文件

```text
KnowledgeFileUploadPanel
  → POST /knowledge-files（files + username）
  → Java 创建知识文件记录并保存 original
  → 后台转换为 Markdown、调用 chat-agent 向量化
  → GET /knowledge-files/events 发出 file-status
  → FileUploadPanel 重新 GET /knowledge-files
```

知识文件的 `originalStorageStatus`、`convertStatus`、`indexStatus` 共同决定表格显示、重试和下载可用性。原文件只有在 `STORED` 且具备路径与 SHA-256 时可下载；Markdown 只有转换完成且具备路径与 SHA-256 时可下载。

### 5.3 资信材料

投标创建页和详情页是两个不同边界：

```text
BidRecordCreate
  → POST /bidder/bid-records 创建当前账号投标记录
  → CredentialFileUploadPanel
  → FileUploadPanel
  → POST /bidder/bid-records/{id}/credential-files（files + username）

MyBids 详情弹窗
  → CredentialFileUploadPanel
  → FileUploadPanel
  → GET /bidder/bid-records/{id}/credential-files
  → GET /bidder/bid-records/{id}/credential-files/events
```

`views/supplier/components/CredentialFileUploadPanel.vue` 只负责把投标记录上下文、资信 API、鉴权和状态文案适配给通用组件，同时由投标录入页与“我的投标”详情复用。上传响应是 `CredentialFileUploadResponse`，只包含上传阶段字段；完整文件元数据只从列表接口读取，不能把两种响应误写成同一个 TypeScript 类型。

投标方所有资信文件请求都走 `/bidder/bid-records/{id}/…`，因此后端可以先从 Basic 认证得到当前账号，再校验 `bid_record.bidder_account_id` 归属。招标方下载则走独立的招标方受保护端点，具体访问范围以 Java Controller/Service 为准。

## 6. API 模块

| 模块 | 前端职责 |
| --- | --- |
| `bid-inviter-account.ts`、`bidder-account.ts` | 注册、登录、当前账号 |
| `invitation-for-bid.ts`、`bid-handler-info.ts`、`bid-record.ts`、`risk-analysis.ts` | 招标方业务页面 |
| `bidder-bid-record.ts` | 当前投标方的投标记录及资信文件上传 |
| `credential-file.ts`、`knowledge-file.ts` | 文件列表、删除、下载和 SSE |
| `chat-agent.ts` | 会话创建/改名/删除、历史消息和问答 |
| `sse.ts` | 带 Basic Header 的通用 SSE 订阅 |

Vite 代理前缀为：`/invitation-for-bid`、`/bid-handler-info`、`/bidder`、`/bid-inviter`、`/bid-record`、`/risk-analysis`、`/credential-files`、`/knowledge-files`、`/chat-agent`、`/service-status`。

