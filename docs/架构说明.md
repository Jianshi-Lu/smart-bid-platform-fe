# 前端架构说明

> 当前最小实现状态,随着端点/模块增加持续更新。

## 一、数据流转链条

```
[View 输入]
  ↓ v-model 监听 input 事件
[reactive(form) 内存对象]
  ↓ createInvitationForBid(form)
[axios.post(JSON.stringify(form))]
  ↓ HTTP Body
[BE 接收并处理]
  ↓
[HTTP Response JSON]
  ↓ axios 自动 JSON.parse
[resp.data (JS 对象)]
  ↓ 赋值
[created.value / successMsg.value]
  ↓ Vue 响应式 Proxy 拦截写入
[Virtual DOM Diff]
  ↓
[浏览器 DOM 更新]
```

## 二、与后端的契约

| 项 | 约定 |
|---|---|
| 信封 | `Result<T> = { code: number; message: string; data: T }` |
| 业务成功 | `code === 200`(HTTP 状态几乎总是 200) |
| 业务失败 | `code` 为 400 / 404 / 500,错误消息在 `message` |
| 路径前缀 | 无 `/api`,直接 `/{module}/...` |
| 时间 | ISO-8601 字符串(对应 BE `LocalDateTime`) |
| 金额 | JSON number(对应 BE `BigDecimal`) |
| 必填字段 | BE 端 `@NotNull` / `@NotBlank` 校验,FE 不做前端校验 |
| 跨域 | Vite 代理转发到 `localhost:8080`,无需 CORS 配置 |

## 三、目录职责

| 目录 | 职责 | 是否依赖 BE |
|---|---|---|
| `src/types/` | 纯 TS 类型,字段对齐 BE DTO/Entity | 是(字段名必须同步) |
| `src/api/` | 纯 axios 封装,不掺杂 UI 逻辑 | 是(端点路径) |
| `src/components/` | Vue 组件,视图 + 事件,调用 `api/` | 否 |
| `src/App.vue` | 应用根,挂载入口组件 | 否 |

依赖方向: `components/` → `api/` → `types/`,**严格单向**。

## 四、关键技术决策

| 决策 | 选择 | 理由 |
|---|---|---|
| SPA vs MPA | SPA | 单页 + 后续 vue-router 友好 |
| 状态管理 | 暂不引入(Pinia 过重) | 当前仅 1 组件,`ref`/`reactive` 够用 |
| UI 库 | 暂不引入(原生 HTML) | 先打通信,后接 Element Plus |
| API 结构 | 方案 C(不抽 `http.ts`) | 端点 < 3,重复代码可控 |
| 鉴权 | 无(BE 暂未加) | 加时再插 `http.ts` 拦截器 |
| 路径别名 | `@/` → `src/` | 避免相对路径 `../../../` |
| 字段校验 | 全部交给 BE | 减少 FE 重复定义,保持单一信任源 |

## 五、当前覆盖范围

- **1 个端点**: `POST /invitation-for-bid/add`
- **1 个组件**: `CreateInvitationForm`(18 字段表单)
- **0 个路由** / **0 个状态库** / **0 个 UI 库依赖**
- **依赖清单**:`vue` 3.5.39 + `axios` 1.x
