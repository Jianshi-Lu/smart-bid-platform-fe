# 前端架构说明

> 当前最小实现状态,随着端点/模块增加持续更新。

## 一、数据流转链条

### Create 链(写入)

```
[View 输入(el-form v-model)]
  ↓ 字段变更触发响应式更新
[reactive(form) 内存对象]
  ↓ submit() 时 ?? 0 兜底数字字段(bidHandlerId / invitationId)
[createXxxForXxx(form)]
  ↓ http.post(JSON.stringify(form))
[HTTP Body → Vite 代理 → BE 8080]
  ↓
[BE 接收 → @Valid 校验 → 写库]
  ↓
[HTTP Response JSON → axios 自动 parse]
  ↓ resp.data.data 解包 envelope
[created.value (实体,含 BE 自动算字段如 bidNo/bidAt)]
  ↓ Vue 响应式 Proxy
[ElMessage.success + <el-card> 展示 JSON]
```

3 个模块的 Create 链完全一致,区别只在初始 reactive form 字段。bid-record 的 `bidNo` / `bidAt` 由 BE 自动算,客户端不传也不显示输入框,创建后从返回 entity 看到。

### List 链(读取)

```
[<el-pagination @current-change>]
  ↓
[reload(page)]
  ↓ listXxxs({page, pageSize, sort})
[http.get → Vite 代理 → BE PageHelper]
  ↓ resp.data.data 解包 envelope
[PageResult<T>(17 字段)]
  ↓ rows.value / total.value / currentPage.value
[<el-table> 7 列 + <el-pagination> total/prev/pager/next/jumper]
```

3 个模块的 List 链完全一致,共用同一套分页/loading/empty 模式。

错误路径(3 模块共用):

```
[http 响应]
  ↓ 响应拦截器 (src/api/http.ts:25-53)
  ↓ code != 200 → ApiError(code, message)
[组件 catch]
  ↓ e instanceof ApiError
[ElMessage.error(`[${e.code}] ${e.message}`)]
```

### Home 链(导航)

```
[Home.vue 渲染 entries 数组(6 张卡: 3 模块 × 2 动作)]
  ↓ 用户点击 el-card
[$router.push(entry.path)]
  ↓ vue-router 查找路由表
[目标 component 懒加载]
  ↓
[目标视图渲染]
```

无网络请求,纯前端跳转。`entries` 是 Home.vue 内的配置数组,加新模块只需追加 2 个对象(模块的 list + create),模板不动。

所有页面外层都由 `App.vue` 提供 sticky 顶部 header(品牌 + 首页/公告列表/创建公告导航)。`List.vue` / `Create.vue` 页面标题右侧提供"返回首页"按钮,作为子页回到导航入口的显式操作。

页面级组件统一套用 `src/style.css` 的 `.page` / `.page-header` / `.page-title` / `.page-actions` / `.page-card` 全局布局类,避免每个页面重复写 inline style 或 scoped 版标题区布局。

### 404 链(未匹配路由)

```
[用户访问未定义路径 /#/xxx]
  ↓ vue-router 通配匹配
[NotFound.vue 渲染]
  ↓ 显示 route.fullPath + "返回首页" 按钮
[$router.push('/')]
  ↓ 跳回 Home.vue
```

## 二、与后端的契约

| 项 | 约定 |
|---|---|
| 信封 | `Result<T> = { code: number; message: string; data: T }` |
| 业务成功 | `code === 200`(HTTP 状态几乎总是 200) |
| 业务失败 | `code` 为 400 / 404 / 500,错误消息在 `message` |
| 路径前缀 | 无 `/api`,直接 `/{module}/...`;3 模块各一组前缀 |
| 分页 | `GET /.../?page=&pageSize=&sort=`,响应 `PageResult<T>`(17 字段,见 src/types/common.ts) |
| 排序字段 | **SQL 列名(snake_case)+ 空格 + 方向**,例 `"invitation_id desc"`,**不是**实体属性名 |
| 时间 | ISO-8601 字符串(对应 BE `LocalDateTime`),date-picker 需 `value-format="YYYY-MM-DDTHH:mm:ss"` |
| 金额 | JSON number(对应 BE `BigDecimal`),`el-input-number :precision="2" :step="0.01"` 保证输入合规 |
| 必填字段 | BE 端 `@NotNull` / `@NotBlank` 校验,FE 不做前端校验 |
| 跨域 | Vite 代理转发到 `localhost:8080`,无需 CORS 配置 |

3 模块 URL 前缀一览:

| 模块 | URL 前缀 | 对齐目标 |
|---|---|---|
| 招标公告 | `/invitation/*` | BE V18 实体名 `InvitationForBid` |
| 招标经办人 | `/bid-handler-info/*` | `src/modules/bid-handler-info/` 目录名 |
| 投标记录 | `/bid-record/*` | `src/modules/bid-record/` 目录名 |

## 二·、错误模型与拦截器策略

### BE 两层错误模型

| 层 | 触发条件 | HTTP 状态 | 响应体 | FE 处理 |
|---|---|---|---|---|
| 第 1 层 | BE 业务错(GlobalExceptionHandler + `Result.error`) | 200 | `Result<T>` 信封 | 判 `body.code != 200` → `ApiError(body.code, ...)` |
| 第 2 层 | Spring/Tomcat 框架错(404 路径不存在 / 405 方法不允许 / 415 Content-Type 错 / 400 JSON 坏) | 4xx/5xx | 非 Result 信封 | 取 `response.status` → `ApiError(status, ...)` |
| 兜底 | 网络错 / CORS / 超时 | 无响应 | - | 原 err 透传(不是 `ApiError`) |

> **关键事实**:BE 所有 `Result.error(...)` 都走 HTTP 200,BE 没有用 `ResponseEntity.status(400)` 的用法。
> **当前拦截器盲点**:第 2 层错误格式 BE 未统一,FE 只能从 HTTP status 推断;若未来 BE 给框架错也返 `Result` 信封,拦截器**自动兼容**(优先从 body 取 code)。

### ApiError 契约

所有 `src/modules/*/api.ts` 抛错都是 `ApiError` 实例。调用方约定:

```ts
import { ApiError } from '@/api/http'

try {
    const data = await createXxx(form)
    // 成功:data 已是 Result.data 解包后的实体
} catch (e) {
    if (e instanceof ApiError) {
        // 业务错或 HTTP 框架错
        // e.code: 业务码(400/404/500)或 HTTP 状态码
        // e.message: BE message 或 "HTTP xxx"
    } else {
        // 网络错等不可恢复异常
    }
}
```

UI 层统一用 `ElMessage.error('[${code}] ${message}')` 弹出,不内联 `<div style="color:red">`。

拦截器源码:`src/api/http.ts:25-53`。

## 三、目录职责

| 目录 | 职责 | 是否依赖 BE |
|---|---|---|
| `src/api/` | 全局 HTTP 基础设施(http 实例 + ApiError + 响应拦截器) | 否(只 import axios) |
| `src/types/common.ts` | 跨特性共享类型(Result/PageResult) | 是(对齐 BE 通用结构) |
| `src/modules/{name}/` | 业务特性聚合(每个特性一个目录,内含 api + types);当前 **3 个特性模块**:invitation-for-bid / bid-handler-info / bid-record | 是(端点 + DTO) |
| `src/views/{Feature}/{Action}.vue` | 页面级组件,按特性分子目录;当前 **3 个特性子目录**:InvitationForBid / BidHandlerInfo / BidRecord,各含 List + Create | 否 |
| `src/views/Home.vue` | 应用导航首页(entries 数组驱动,响应式卡片) | 否 |
| `src/views/NotFound.vue` | 404 页面(通配路由兜底) | 否 |
| `src/router/` | vue-router 路由表(7 条 + 1 通配) | 否(只 import views) |
| `src/shared/` | 跨特性复用(composables/components/utils,暂仅占位) | 否 |
| `src/assets/` | 静态资源(图片/CSS) | 否 |
| `src/style.css` | 全局基础样式 + 页面级 layout class(`.page*`) | 否 |
| `src/App.vue` | 应用根,sticky 顶部 header(品牌 + nav) + `<router-view>` | 否 |
| `src/main.ts` | 应用入口,app.use(router) + app.use(ElementPlus) | 否 |

依赖方向:

```
views/ → modules/{name}/{api,types} → types/common.ts
       → api/http.ts (ApiError, http)
       → router/ (URL)
```

**严格单向**,不允许反向依赖。`views/` 不应被 `api/` 或 `router/` 引用。

## 四、关键技术决策

| 决策 | 选择 | 理由 |
|---|---|---|
| SPA vs MPA | SPA + vue-router 5 | 单页 + hash 模式无需服务器 fallback |
| 状态管理 | 暂不引入 Pinia | 当前 3 模块,`ref`/`reactive` 够用;跨页面共享需求出现时再升级 |
| UI 库 | Element Plus 2.10+(全局注册) | 表格/分页/表单/Toast 一站式;**不**引 unplugin-auto-import,显式 import 行为可控 |
| 错误通知 | ElMessage(全局 toast) | 拦截器抛 ApiError,组件统一 `ElMessage.error('[code] message')`,不内联红色 div |
| API 结构 | 方案 B (`http.ts` + 拦截器 + `ApiError`) | 集中 envelope 翻译,组件零模板;3 模块共用 |
| 鉴权 | 无(BE 暂未加) | 加时再插 `http.ts` 请求拦截器注入 `Authorization` 头 |
| 路径别名 | `@/` → `src/` | 避免相对路径 `../../../` |
| 字段校验 | 全部交给 BE | 减少 FE 重复定义,保持单一信任源 |
| 目录结构 | 按特性分层(`modules/` + `views/`) | 解决"特性代码散落多个顶层目录"问题,新特性加 `modules/{name}/` + `views/{Feature}/` 即可 |
| 页面布局 | 全局 `.page*` class + 页面局部 scoped 样式 | 统一页面外层宽度/标题区/操作区,避免每页重复 inline style |
| 路由命名 | URL 前缀对齐模块目录名(kebab-case) | `/invitation/*` 对齐 BE V18 实体名;`/bid-handler-info/*` `/bid-record/*` 对齐模块目录名 |
| Home 入口 | 扁平 6 卡(3 模块 × 2 动作) | 3 模块各 2 动作规模适中,直接扁平展示;未来模块数 ≥ 5 时考虑引入模块分组页 |

## 五、当前覆盖范围

- **6 个端点**(3 模块 × 2 端点):
  - `POST /invitation/add` 创建公告
  - `GET /invitation` 分页查询公告(PageHelper)
  - `POST /bid-handler-info/add` 创建经办人
  - `GET /bid-handler-info` 分页查询经办人(PageHelper)
  - `POST /bid-record/add` 创建投标记录
  - `GET /bid-record` 分页查询投标记录(PageHelper)
- **8 个视图**:
  - `views/Home.vue` 导航首页(6 个 entries 卡片)
  - `views/NotFound.vue` 404 页面
  - `views/InvitationForBid/List.vue` 7 列表格 + 翻页
  - `views/InvitationForBid/Create.vue` 18 字段表单
  - `views/BidHandlerInfo/List.vue` 5 列表格 + 翻页
  - `views/BidHandlerInfo/Create.vue` 4 字段表单
  - `views/BidRecord/List.vue` 7 列表格 + 翻页
  - `views/BidRecord/Create.vue` 5 字段表单(4 必填 + 1 可选)
- **8 条路由**(7 + 1 通配):
  - `/` → Home.vue
  - `/invitation/list` → 公告列表
  - `/invitation/create` → 创建公告
  - `/bid-handler-info/list` → 经办人列表
  - `/bid-handler-info/create` → 新建经办人
  - `/bid-record/list` → 投标列表
  - `/bid-record/create` → 新建投标
  - `/:pathMatch(.*)*` → NotFound.vue(非 redirect)
- **0 个状态库** / **不引** Pinia
- **依赖清单**:
  - `vue` 3.5.39
  - `vue-router` 5.1.0
  - `axios` 1.x
  - `element-plus` 2.10+
  - `@element-plus/icons-vue`(Home.vue 已用 `Document` / `Plus` / `List` / `User` / `UserFilled`)
