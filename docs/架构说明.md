# 前端架构说明

> 当前最小实现状态,随着端点/模块增加持续更新。

## 一、数据流转链条

### Create 链(写入)

```
[View 输入(el-form v-model)]
  ↓ 字段变更触发响应式更新
[reactive(form) 内存对象]
  ↓ submit() 时兜底数字字段(bidHandlerId / invitationId / quotePrice)
[createXxxForXxx(form)]
  ↓ http.post(JSON.stringify(form))
[HTTP Body → Vite 代理 → BE 8080]
  ↓
[BE 接收 → @Valid 校验 → 写库]
  ↓
[HTTP Response JSON → axios 自动 parse]
  ↓ resp.data.data 解包 envelope
[created.value (实体,含 BE 自动算字段如 bidNo/bidAt)]
  ↓ Vue 响应式 Proxy
[ElMessage.success + 页面成功态]
```

创建链在招标公告、经办人、投标记录 3 个写入端点上复用同一套模式；投标方投标录入页复用 `createBidRecord`，但会先从 query 加载选中公告详情。bid-record 的 `bidNo` / `bidAt` 由 BE 自动算，客户端不传也不显示输入框；投标方页面从创建响应直接取得 `bidRecordId`，不再发起查询请求。

### 资信材料上传当前边界

`CredentialFileUpload.vue` 已实现文件选择、上传、追加上传和删除，并要求父级传入已落库的正整数 `bidRecordId`。投标录入页始终展示上传卡片：创建投标前传入 `bidRecordId=null` 并禁用组件；创建成功后从 `createBidRecord` 响应保存 ID、锁定投标表单，再通过 prop 解锁上传组件。创建失败时 ID 保持为空，上传链不会启动。

`uploadCredentialFiles` 发送 `files`、`bidRecordId` 和可选 `uploadBatchId`；当前后端 `FileUploadController.upload()` 接收 `bidRecordId`，并在本次请求内生成 `uploadBatchId`，将原始文件和文件元数据落盘/落库。上传接口不会在同一请求内自动转换；转换可由 `FileConvertController` 的独立端点触发，也可由风险分析入口按需触发。

### List 链(读取)

```
[<el-pagination @current-change>]
  ↓
[usePagedList.load(page)]
  ↓ 组装 PageRequest({page, pageSize, sort})
[listXxxs(query)]
[http.get → Vite 代理 → BE PageHelper]
  ↓ resp.data.data 解包 envelope
[PageResult<T>(18 字段)]
  ↓ 仅最新请求可写入 rows / total / currentPage
[<el-table> 7 列 + <el-pagination> total/prev/pager/next/jumper]
```

5 个列表页复用 `shared/composables/usePagedList.ts`。composable 统一管理分页、loading、错误回调，并用递增请求序号忽略较慢的旧响应，避免快速翻页时旧页覆盖新页。

错误路径(所有 API 模块共用):

```
[http 响应]
  ↓ 响应拦截器 (src/api/http.ts)
  ↓ success=false 或 HTTP 非 2xx → ApiError(code/status, message)
[页面 / composable catch]
  ↓ getErrorMessage(error)
[ElMessage.error(统一展示文案)]
```

### 角色选择链(进站分流)

```
[用户访问 / ]
  ↓ vue-router 匹配根路由
[RoleSelector.vue 根据 roles 数组渲染 2 个入口]
  ↓ 用户点击 router-link(招标方/投标方)
[/purchaser 或 /supplier]
  ↓ vue-router 查找路由表
[对应 Home 组件懒加载]
  ↓
[对应角色首页渲染]
```

进站先选角色(招标方/投标方),后续按角色分流到对应入口。招标方已实现 4 个模块入口，投标方首页提供投标项目列表入口。

### 招标方首页链(PurchaserHome 导航 - 模块化)

```
[PurchaserHome.vue 渲染 groups 数组(4 张 group card: 招标公告/经办人/投标/风险分析)]
  ↓ group card 自身不点击,只触发 hover 阴影
[卡内 router-link 列表(每个模块的子动作: 列表/创建等)]
  ↓ 用户点击 router-link
[$router.push(action.path)]    // path 以 /purchaser 为前缀
  ↓ vue-router 查找路由表
[目标 component 懒加载]
  ↓
[目标视图渲染]
```

无网络请求,纯前端跳转。`groups` 是 PurchaserHome.vue 内的配置数组(结构: `Group { title, description, icon, actions[] }`),actions 内每个对象有 `label` / `path` / `icon`。所有 path 以 `/purchaser/` 为前缀。加新模块只需在 groups 数组追加一个对象,模板不动。卡内子项底部对齐(`display: flex; flex-direction: column` + `margin-top: auto`),让"风险分析"(1 个 action) 与其他 3 个模块(2 个 action) 视觉对齐。

所有页面外层都由 `App.vue` 提供 sticky 顶部 header(品牌 = 跳回 / 角色选择器)。业务页复用 `PageHeader.vue`；招标方页面返回 `/purchaser`，投标方页面返回 `/supplier` 或所属列表，根路径只承担角色选择。

页面级组件统一套用 `src/style.css` 的 `.page` / `.page-header` / `.page-title` / `.page-actions` / `.page-card` 全局布局类,避免每个页面重复写 inline style 或 scoped 版标题区布局。

### 404 链(未匹配路由)

```
[用户访问未定义路径 /#/xxx]
  ↓ vue-router 通配匹配
[NotFound.vue 渲染]
  ↓ 显示 route.fullPath + "返回首页" 按钮
[$router.push('/')]
  ↓ 跳回 Home.vue
```

### 风险分析触发链(行内操作,bid-record 列表页扩展)

```
[<el-button @click="onAnalyzeRisk(row)"> 行末"风险分析"按钮]
  ↓ 用户点击
[onAnalyzeRisk(row),置 analyzingId = row.bidRecordId]
  ↓ UI 反馈(按钮 loading + 文案"分析中..." + 其他行 disabled)
[analyzeRisk(row.bidRecordId)]
  ↓ http.post<Result<RiskAnalysis>>(`/bid-record/analyze-risk/${id}`)
[http 实例 → Vite 代理 → BE 8080]
  ↓
[BE RiskAnalysisController.analyzeRisk]
  ↓ 检查批次/文件；必要时自动转换 → 汇总 Markdown → 同步调用 OpenAI 兼容模型
  ↓ 解析 JSON → 落库 risk_analysis 表 → 返回最新 RiskAnalysis
[BE 返回 Result<RiskAnalysis>,拦截器拆 envelope]
  ↓ resp.data.data
[currentAnalysis.value = analysis 实体]
  ↓ Vue 响应式 Proxy
[el-dialog 弹窗展示 8 字段(分析ID/记录ID/投标人/等级/摘要/建议/版本/时间)]
  +
[ElMessage.success(`风险分析完成,等级=${riskLevel}`)]
```

错误链(任一步骤抛错): ApiError / 网络错误 → getErrorMessage → ElMessage.error
                   + analyzingId 置 null → 按钮恢复

并发控制: 同一时刻只能分析一行(analyzingId !== null 时其他行按钮 disabled),
         避免结果混淆 / 多个并发模型请求

## 二、与后端的契约

| 项 | 约定 |
|---|---|
| 信封 | `Result<T> = { success: boolean; code: string; message: string; data: T }`，失败时可带模块、操作和阶段信息 |
| 业务成功 | HTTP 200，`success=true`，`code="SUCCESS"` |
| 业务失败 | HTTP 状态表达协议结果，`success=false`，`code` 为模块化错误码，如 `RISK_ANALYSIS.INPUT_NOT_READY` |
| 路径前缀 | 无 `/api`,直接 `/{module}/...`;5 个业务前缀 + `/service-status` 代理 |
| 分页 | `GET /.../?page=&pageSize=&sort=`,响应 `PageResult<T>`(18 字段,见 src/types/common.ts) |
| 排序字段 | **SQL 列名(snake_case)+ 空格 + 方向**,例 `"invitation_id desc"`,**不是**实体属性名 |
| 时间 | ISO-8601 字符串(对应 BE `LocalDateTime`),date-picker 需 `value-format="YYYY-MM-DDTHH:mm:ss"` |
| 金额 | JSON number(对应 BE `BigDecimal`),`el-input-number :precision="2" :step="0.01"` 保证输入合规 |
| 必填字段 | BE 端 `@NotNull` / `@NotBlank` 校验,FE 不做前端校验 |
| 跨域 | Vite 代理转发到 `localhost:8080`,无需 CORS 配置 |

5 模块 URL 前缀一览:

| 模块 | URL 前缀 | 对齐目标 |
|---|---|---|
| 招标公告 | `/invitation-for-bid/*` | BE V18 实体名 `InvitationForBid` |
| 招标经办人 | `/bid-handler-info/*` | `src/api/bid-handler-info.ts` 文件名 |
| 投标记录 | `/bid-record/*` | `src/api/bid-record.ts` 文件名 |
| 风险分析 | `/risk-analysis/*` | BE 独立 `RiskAnalysisController`,只读入口 |
| 资信文件 | `/credential-files/*` | multipart 上传、转换与批次内文件删除；上传请求携带 `bidRecordId` |

## 二·、错误模型与拦截器策略

### BE 两层错误模型

| 层 | 触发条件 | HTTP 状态 | 响应体 | FE 处理 |
|---|---|---|---|---|
| 第 1 层 | BE 业务错(GlobalExceptionHandler + `Result.failure`) | 按错误码返回 | `Result<T>` 信封 | 判 `success=false`，优先使用 `body.code` → `ApiError(body.code, ...)` |
| 第 2 层 | Spring/Tomcat 框架错(404 路径不存在 / 405 方法不允许 / 415 Content-Type 错 / 400 JSON 坏) | 4xx/5xx | 非 Result 信封 | 取 `response.status` → `ApiError(status, ...)` |
| 兜底 | 网络错 / CORS / 超时 | 无响应 | - | 原 err 透传(不是 `ApiError`) |

> **当前事实**:业务异常由 `GlobalExceptionHandler` 统一转成结构化 `Result`，HTTP 状态码与模块化 `code` 分别承载协议结果和业务语义。
> **当前拦截器兼容策略**:若 HTTP 错误响应包含 `Result` 信封则优先读取其中的 `code/message`，否则退回使用 HTTP status。

### ApiError 契约

业务错误与 HTTP 框架错误由拦截器转成 `ApiError`，网络错误保留原异常。调用方统一通过展示适配器处理:

```ts
import { getErrorMessage } from '@/shared/utils/error'

try {
    const data = await createXxx(form)
    // 成功:data 已是 Result.data 解包后的实体
} catch (error) {
    ElMessage.error(getErrorMessage(error))
}
```

`ApiError` 定义在 `shared/errors`，HTTP 拦截器和展示适配器分别依赖它，避免 shared 反向依赖 API 层。`getErrorMessage` 对 `ApiError` 保留 `[code] message`，对普通异常补 `请求失败:` 前缀；上传组件可传空前缀，避免上下文文案重复。

错误类型:`src/shared/errors/api-error.ts`；拦截器:`src/api/http.ts`；展示适配器:`src/shared/utils/error.ts`。

## 三、目录职责

| 目录 | 职责 | 是否依赖 BE |
|---|---|---|
| `src/api/` | 全局 HTTP 基础设施(http 实例 + 响应拦截器)与业务 API | 是(业务模块对齐 BE 端点) |
| `src/types/common.ts` | 跨特性共享类型(Result/PageRequest/PageResult/Diff) | 是(对齐 BE 通用结构) |
| `src/api/{name}.ts` + `src/types/{name}.ts` | 业务 API 与类型(扁平结构);当前 **5 个特性**:bid-handler-info / bid-record / invitation-for-bid / risk-analysis / credential-file | 是(端点 + DTO) |
| `src/views/purchaser/` | 招标方所有视图(与 /purchaser/* 路由对齐);含 Home + 4 个业务子目录(InvitationForBid/BidHandlerInfo/BidRecord/RiskAnalysis) | 否 |
| `src/views/supplier/` | 投标方所有视图(与 /supplier/* 路由对齐);含 Home + InvitationList + BidRecordCreate | 否 |
| `src/views/common/` | 全局通用视图(与 / 通配路由对齐);含 NotFound + RoleSelector | 否 |
| `src/router/` | vue-router 路由表(14 条总计:13 个明确入口 + 1 通配 404,角色入口分层) | 否(只 import views) |
| `src/shared/components/` | 跨页面 UI 边界(PageHeader / CredentialFileUpload) | 否 |
| `src/shared/composables/` | 跨页面状态逻辑(usePagedList:分页、loading、并发旧响应保护) | 否 |
| `src/shared/errors/` | 与传输实现无关的标准错误类型(ApiError) | 否 |
| `src/shared/utils/` | 纯展示工具(error / format / el-tag) | 否 |
| `src/assets/` | 静态资源(图片/CSS) | 否 |
| `src/style.css` | 全局基础样式 + 页面级 layout class(`.page*`) | 否 |
| `src/App.vue` | 应用根,sticky 顶部 header(品牌 + nav) + `<router-view>` | 否 |
| `src/main.ts` | 应用入口,app.use(router) + app.use(ElementPlus) | 否 |

依赖方向:

```
views/ → api/{name} + types/{name} → types/common.ts
       → shared/components + shared/composables + shared/errors + shared/utils
       → router/ (URL)
api/{name}.ts → api/http.ts → shared/errors/api-error.ts
shared/utils/error.ts → shared/errors/api-error.ts
```

**严格单向**,不允许反向依赖。`views/` 不应被 `api/` 或 `router/` 引用。

`CredentialFileUpload.vue` 是当前唯一的业务感知型复用组件，会调用 credential-file API 并使用对应 DTO；`PageHeader` 等通用 UI 不依赖业务 API。若后续出现第二组资信文件页面或更多同类业务组件，再将其整体迁入 `features/credential-file/`，避免现在只为目录形式做无收益搬迁。

## 四、关键技术决策

| 决策 | 选择 | 理由 |
|---|---|---|
| SPA vs MPA | SPA + vue-router `^5.1.0`,hash 模式 | 单页 + hash 模式无需服务器 fallback |
| 状态管理 | 暂不引入 Pinia | 当前 4 模块,`ref`/`reactive` 够用;跨页面共享需求出现时再升级 |
| UI 库 | Element Plus `^2.14.2`(全局注册) | 表格/分页/表单/Toast 一站式;**不**引 unplugin-auto-import,显式 import 行为可控 |
| 错误通知 | `getErrorMessage` + ElMessage | 拦截器负责异常类型，shared 工具负责展示文案，页面不重复判断 ApiError |
| API 结构 | `http.ts` + 拦截器；`shared/errors/ApiError` | 集中 envelope 翻译，错误类型保持传输层无关，5 个业务 API 模块共用 |
| 鉴权 | 无(BE 暂未加) | 加时再插 `http.ts` 请求拦截器注入 `Authorization` 头 |
| 路径别名 | `@/` → `src/` | 避免相对路径 `../../../` |
| 字段校验 | 全部交给 BE | 减少 FE 重复定义,保持单一信任源 |
| 目录结构 | 按角色分层(`views/purchaser/` `views/supplier/` `views/common/`)+ 业务模块分子目录(`purchaser/{InvitationForBid,BidHandlerInfo,BidRecord,RiskAnalysis}/`) | views 与路由 1:1 对应;业务模块归属角色目录;新角色加 `views/{role}/` 即可 |
| 页面布局 | 全局 `.page*` class + `PageHeader` + 页面局部 scoped 样式 | 统一页面外层宽度、返回语义和窄屏布局 |
| 分页状态 | `usePagedList<T>` | 5 个列表共享分页/loading/error，并忽略晚到的旧请求 |
| 路由命名 | URL 前缀分两层: 角色(purchaser/supplier) + 业务模块(kebab-case) | `/purchaser` 是招标方入口,`/supplier` 是投标方入口,业务路径跟角色下;`/purchaser/invitation/*` 对齐 BE V18 实体名,`/purchaser/bid-handler-info/*` 等对齐模块目录名 |
| 角色入口分层 | 进站 / 必选角色(purchaser/supplier),业务路由按角色分组 | 后续投标方业务实现时,在 /supplier/* 下挂子路由即可,不影响 /purchaser/* 结构 |
| Home 入口 | 招标方首页 PurchaserHome.vue 模块化 4 group card(4 模块,卡内 router-link 子项) | 7 张扁平卡 → 4 张模块卡,卡内嵌套子项链接;card 自身不点击,只触发 hover 阴影;子项底部对齐(`flex` + `margin-top: auto`);加新模块在 groups 数组追加一个对象即可 |
| risk-analysis 模块独立 | 与 BE 端独立 `RiskAnalysisController` 对齐 | 后端明确为敏感风险数据提供前端只读入口,不暴露 DELETE/PATCH/POST 写端点;FE 同步分离为独立模块,`RiskAnalysis` 类型从 `bid-record` 迁出;`bid-record → risk-analysis` 跨模块单向依赖 |

## 七、Home.vue 模块化设计 (m0771-m0801)

详见 `src/views/purchaser/Home.vue` 顶部注释 + git log。

**目标**: 把 7 张扁平 entry 卡片(每个动作 1 卡)重构成 4 张 group 卡片(每模块 1 卡),卡内嵌套子项链接。

**数据契约**:
```ts
interface HomeAction { label: string; path: string; icon: Component }
interface HomeGroup  { title: string; description: string; icon: Component; actions: HomeAction[] }
```

**当前 4 groups**:
1. 招标公告 (Document 图标): 公告列表 + 创建公告
2. 招标经办人 (User 图标): 经办人列表 + 新建经办人
3. 投标记录 (List 图标): 投标列表 + 新建投标
4. 风险分析 (DataAnalysis 图标): 风险分析列表 (只读,无创建)

**关键设计决策**:
- group card 自身**不绑定跳转**(@click 不加),只触发 hover 阴影(`shadow="hover"`),避免用户误以为整张卡可点击
- 子项用 `<router-link>` 列表渲染,不是 `<el-button>`,保持"导航目录"语义而非"操作按钮"
- 4 张卡用 `<el-col :xs="24" :sm="12" :md="12" :lg="6">` 响应式:小屏 1 列 / 中屏 2 列 / 大屏 4 列
- 子项底部对齐用 `display: flex; flex-direction: column` + `margin-top: auto`,让"风险分析"(1 个 action) 与其他 3 模块(2 个 action) 视觉等高对齐

**踩坑**:
- el-card 默认是 flex column,body 默认 `flex-grow: 1`,**不要**给 body 加 `height: 100%`,否则 body 高度 = card content-box - padding,内容溢出被 el-card 的 `overflow: hidden` 裁掉 → 组件看起来是空的(只显示 card header)。修复: 只加 `display: flex; flex-direction: column`,由 `flex-grow: 1` 自动撑满

## 十、文件级注释约定

文件顶部注释只记录职责、跨层边界、业务不变量和不明显的失败条件。不要逐行复述 `ref`、`try/catch`、模板列数或固定行号；这类注释会在抽取 composable 或组件后迅速失真。

- API 文件记录 HTTP method/path、入参与返回契约。
- 类型文件记录与后端 DTO 的映射和特殊序列化约束。
- View 文件记录页面职责和特有业务操作；通用分页链直接引用 `usePagedList`。
- 复杂的端到端调用链维护在本架构文档，不复制到每个页面。
- 代码旁注只解释不明显的约束，例如忽略旧分页响应、复用后端返回的 uploadBatchId。
