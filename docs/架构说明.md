# 前端架构说明

> 当前最小实现状态,随着端点/模块增加持续更新。

## 一、数据流转链条

```
[View 输入]
  ↓ v-model 监听 input 事件
[reactive(form) 内存对象]
  ↓ createInvitationForBid(form)
[axios.post(JSON.stringify(form))]
  ↓ HTTP Body
[BE 接收并处理]
  ↓
[HTTP Response JSON]
  ↓ axios 自动 JSON.parse
[resp.data (JS 对象)]
  ↓ 赋值
[created.value / successMsg.value]
  ↓ Vue 响应式 Proxy 拦截写入
[Virtual DOM Diff]
  ↓
[浏览器 DOM 更新]
```

## 二、与后端的契约

| 项 | 约定 |
|---|---|
| 信封 | `Result<T> = { code: number; message: string; data: T }` |
| 业务成功 | `code === 200`(HTTP 状态几乎总是 200) |
| 业务失败 | `code` 为 400 / 404 / 500,错误消息在 `message` |
| 路径前缀 | 无 `/api`,直接 `/{module}/...` |
| 时间 | ISO-8601 字符串(对应 BE `LocalDateTime`) |
| 金额 | JSON number(对应 BE `BigDecimal`) |
| 必填字段 | BE 端 `@NotNull` / `@NotBlank` 校验,FE 不做前端校验 |
| 跨域 | Vite 代理转发到 `localhost:8080`,无需 CORS 配置 |

## 二·、错误模型与拦截器策略

### BE 两层错误模型

| 层 | 触发条件 | HTTP 状态 | 响应体 | FE 处理 |
|---|---|---|---|---|
| 第 1 层 | BE 业务错(GlobalExceptionHandler + `Result.error`) | 200 | `Result<T>` 信封 | 判 `body.code != 200` → `ApiError(body.code, ...)` |
| 第 2 层 | Spring/Tomcat 框架错(404 路径不存在 / 405 方法不允许 / 415 Content-Type 错 / 400 JSON 坏) | 4xx/5xx | 非 Result 信封 | 取 `response.status` → `ApiError(status, ...)` |
| 兜底 | 网络错 / CORS / 超时 | 无响应 | - | 原 err 透传(不是 `ApiError`) |

> **关键事实**:BE 所有 `Result.error(...)` 都走 HTTP 200,BE 没有用 `ResponseEntity.status(400)` 的用法。
> **当前拦截器盲点**:第 2 层错误格式 BE 未统一,FE 只能从 HTTP status 推断;若未来 BE 给框架错也返 `Result` 信封,拦截器**自动兼容**(优先从 body 取 code)。

### ApiError 契约

所有 `src/api/*` 模块抛错都是 `ApiError` 实例。调用方约定:

```ts
import { ApiError } from '@/api/http'

try {
    const data = await createInvitationForBid(form)
    // 成功:data 已是 Result.data 解包后的实体
} catch (e) {
    if (e instanceof ApiError) {
        // 业务错或 HTTP 框架错
        // e.code: 业务码(400/404/500)或 HTTP 状态码
        // e.message: BE message 或 "HTTP xxx"
    } else {
        // 网络错等不可恢复异常
    }
}
```

拦截器源码:`src/api/http.ts:25-53`。

## 三、目录职责

| 目录 | 职责 | 是否依赖 BE |
|---|---|---|
| `src/types/` | 纯 TS 类型,字段对齐 BE DTO/Entity | 是(字段名必须同步) |
| `src/api/` | 纯 axios 封装,不掺杂 UI 逻辑 | 是(端点路径) |
| `src/components/` | Vue 组件,视图 + 事件,调用 `api/` | 否 |
| `src/App.vue` | 应用根,挂载入口组件 | 否 |

依赖方向: `components/` → `api/` → `types/`,**严格单向**。

## 四、关键技术决策

| 决策 | 选择 | 理由 |
|---|---|---|
| SPA vs MPA | SPA | 单页 + 后续 vue-router 友好 |
| 状态管理 | 暂不引入(Pinia 过重) | 当前仅 1 组件,`ref`/`reactive` 够用 |
| UI 库 | 暂不引入(原生 HTML) | 先打通信,后接 Element Plus |
| API 结构 | 方案 B (`http.ts` + 拦截器 + `ApiError`) | 集中 envelope 翻译,组件零模板 |
| 鉴权 | 无(BE 暂未加) | 加时再插 `http.ts` 拦截器 |
| 路径别名 | `@/` → `src/` | 避免相对路径 `../../../` |
| 字段校验 | 全部交给 BE | 减少 FE 重复定义,保持单一信任源 |

## 五、当前覆盖范围
